# 悬浮球用量告警 — UI 设计定稿(v2.0 特性)

> 状态:**阈值告警已实现(开工卡 J:UI 层;开工卡 K v2:通知通道 + 触发状态机 +
> 重启去重,插件 1.2.0)**;跨窗同步(面板写入主动推送)仍待后续。
> 设计稿:`token-alert-ui.html`(本目录,双击可开,含可交互演示);亮暗双主题均已核对。
> 视觉规格以设计稿为准;本文是其正式表述与编码交接清单。

---

## 1. 目标与范围

- 每个监控项(供应商)独立设置 **5 小时窗口告警阈值**:开关(默认关)+ 滑杆(5–100%,步进 1,默认 80%)。
- 用量达到阈值 → **立即发一条 Windows 应用通知**(每个窗口周期最多一条,不刷屏)。
- 悬浮球与面板卡片呈现告警态。
- 范围外(v2 再评估):周窗口阈值、声音、邮件、通知点击跳转。

## 2. 交互规格

### 触发状态机(edge-trigger,一次性)

- **评估时机**:该供应商每次成功取数后(轮询 tick / 手动刷新 / 录入 Key 即刷)。
- **触发**:5h% ≥ 阈值 且当前未处于已触发态 → 发通知一次,进入告警态。
- **再武装**:窗口重置(`nextResetTime` 变化)或 5h% < 阈值 → 清除告警态。
- **重启去重**:kv 持久化 `firedAt + resetAt`;同一窗口内重启应用不重发。
- **通知文案**:标题「用量告警」;正文「{名称} 5 小时用量已达 {pct}%,超过阈值 {thr}%。」

> **实现口径(功能卡 K v2)**:UI 告警态为活派生(每次渲染重算,pct < 阈值即灭);
> 通知去重按窗口周期 —— `tm.alertState.<scope>` 记录已通知窗口的 resetAt,同窗口
> 不重发、resetAt 变化即重新武装;评估仅球实例当前账号(轮询粒度)。

### 关键决策:球窗隐藏后继续评估

批次 3 行为是「隐藏即停轮询」;告警语义要求隐藏时仍能发现超限 → **改为:球窗隐藏后
轮询与评估继续(仅跳过 UI 更新),插件停用才停止**。功耗代价可忽略(间隔 ≥120s)。

## 3. 视觉规格(全部走既有 CSS token,零新色)

- **阈值行**:`[供应商缩写 chip] [switch 34×19] [滑杆(4px 轨道、14px thumb、accent 填充)] [数值%]`;
  禁用态整行 opacity .45、滑杆不可交互;行距与既有设置行一致。
- **球体告警态**:外圈脉冲(r=35、stroke 3、danger,2.4s 呼吸,opacity .16↔.5、scale 1↔1.07)
  + 右上角 10px danger 徽标(2px panel 描边);`prefers-reduced-motion` 下静态外圈。
- **面板卡片告警 chip**:danger-soft 底 + danger 字 + bell-ring 图标,999px 胶囊。
- **tooltip 告警行**:danger-soft 底,「已超阈值 {thr}% · 已于 {time} 通知」。
- **Windows 通知**:系统按其主题渲染;应用只控标题与正文(见 §2)。

### 实现口径(UI 层落地修正 —— 开工卡 J,已随 UI 层落地)

- **粒度**:实现是多账号模型(`tm.accounts`,scope = `provider:label`)—— 本文的
  「每供应商」落地为「每账号一行」;阈值行、存储键、状态机键全部按账号 scope。
- **tooltip**:本文 §3 的 DOM 弹层为示意;实际球 tooltip 是 `ball.title` 原生文本,
  告警行落地为 title 文本追加「已超阈值 {thr}%」(无样式;「已于 {time} 通知」
  属功能卡的状态机信息,UI 层不出现)。
- **写入者**:阈值配置仅面板实例写(单写者,与 `tm.accounts` 约定一致),球实例只读;
  面板写入不跨窗通知,球在下次取数/账号切换时读到新配置(跨窗同步归功能卡)。
- **孤儿键**:删除账号后 `tm.alert.<scope>` 残留不清理(读侧无害),清理策略归功能卡。
