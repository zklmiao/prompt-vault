【任务】给 Prompt Vault 增加使用统计:每条 prompt 记录复制次数与最近复制时间,支持按「最近复制 / 最常复制」排序。

【项目背景】项目在 <项目根目录>,Tauri 2 + React 19 + TS。数据单 JSON;PromptItem 字段见 src/types.ts;解析纠偏在 src/util.ts 的 coerceItems;主窗口写盘走 App.tsx 的 persist(write_data,原子写+.bak)。复制入口有两处:主窗口 App.tsx 的 handleCopy/handleCopyFilled(带占位符时会走 PlaceholderModal),以及快速拾取窗口 src/QuickPick.tsx 的 pick/onConfirm(复制后调用 hideQuickpick)。两个窗口共享同一个数据文件,quickpick 不持有主窗口内存态——注意并发写覆盖问题。

【需求与交互设计】
1. 数据结构:PromptItem 增加可选字段 copyCount?: number、lastCopiedAt?: string。coerceItems 兼容(缺失视为 0/undefined);导入合并时 copyCount 取两者较大值、lastCopiedAt 取较新者。
2. 统计写入统一走新增 Rust 命令 bump_copy_stats(path, id):
   - 读文件 → 找到 id → copyCount+1、lastCopiedAt=now → 原子写(复用现有 write_data 的原子写实现,抽成内部函数);全程用全局 Mutex 串行化,避免两窗口同时复制时读改写竞态;
   - 成功后 app.emit_to("main", "stats-changed", ());
   - 主窗口同时也有本地更新路径,见下。
3. 主窗口复制:复制成功后调用 bump_copy_stats,并同步更新内存 items 的 copyCount/lastCopiedAt(直接 setItems,不要再 persist,否则二次写盘)。quickpick 复制:同样调用 bump_copy_stats,然后隐藏;主窗口 listen("stats-changed") → 静默重读数据文件刷新 items(复用 loadFrom 的读取部分,不重建 UI;保持 selectedId)。这保证 quickpick 的计数最终进入主窗口内存态。
4. 排序:侧栏列表头(list-head)右侧加一个小 select(或图标菜单):「最近更新(默认)/ 最近复制 / 最常复制」,选择记 localStorage("pv-sort")。排序规则:置顶组永远在前;组内按所选键降序(最近复制无记录者排后,其次按 updatedAt)。列表行副行/详情 meta 展示「已复制 N 次 · 最近 X」(formatDate)。
5. 验收时注意:复制次数只在成功写剪贴板后 +1;失败不计数。

【实现要点】
- 新 Rust command bump_copy_stats 需要 AppHandle 参数(用于 emit);注册到 invoke_handler;api.ts 加包装。
- 主窗口 listen("stats-changed") 的注册与清理按现有 listen 模式(App.tsx 里已有 hidden-to-tray/clipboard-new 的先例);浏览器预览无事件系统,包 try/catch。
- QuickPick.tsx 复制成功后:await bumpCopyStats(path, id) → hideQuickpick();bump 失败只 console/忽略,不影响复制与隐藏。
- 排序在 App.tsx 的 filtered useMemo 内实现,加 sortMode state。
- 兼容旧数据:无 copyCount 的按 0 处理,不要写默认值进文件(首次 bump 才出现该字段)。

【边界与异常】
- 数据文件被外部修改导致 bump 解析失败:静默失败(复制成功优先),不要弹错误。
- 同时连按两次复制:Mutex 保证两次 +2 不丢。
- 导入(合并)后统计字段按规则合并;覆盖导入则保持文件原值。
- 导出包含统计字段(自然包含,无需特殊处理)。

【不要做的事】
- 不要引入统计图表/仪表盘;不要记录复制内容本身(隐私);不要动占位符 lastValues 的既有逻辑。
