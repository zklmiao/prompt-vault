我们是deepseek, 你现在有无限的token预算，不用关心token消耗；保证产出质量是第一要义；

【任务】给 Prompt Vault 增加拖拽导入:拖 .json 进窗口走导入流程,拖文本文件/纯文本进窗口直接新建 prompt。

【项目背景】项目在 <项目根目录>,Tauri 2 + React 19 + TS。数据是单个 JSON(id/title/body/tags/source/note/pinned/createdAt/updatedAt/lastValues/deletedAt),Rust 命令已有:read_data(path) 读任意文本文件、write_data、get_data_path、choose_export_file 等,前端包装在 src/api.ts。导入现有逻辑:App.tsx 的 handleImportPick(选文件→read_data→coerceItems→ImportChoiceModal 合并/覆盖)与 handleImportApply;新建逻辑:startNew/newFromClipboard → setPrefillBody + setMode({kind:"new"})。工具函数 coerceItems 在 src/util.ts。界面中文,两栏布局。

【需求与交互设计】
1. 在主窗口(main)监听 Tauri 原生拖放事件:getCurrentWebviewWindow().onDragDropEvent(...),事件含 enter/over/drop/leave。不要依赖 HTML5 ondrop(Tauri 开启 dragDropEnabled 时会拦截原生事件,HTML5 drop 不触发)。quickpick 窗口不挂该事件。
2. 拖入窗口时显示全屏半透明遮罩(overlay 样式,复用 token --overlay 的浅化版或自定义),文案"松开以导入 JSON / 新建文本",leave 或 drop 后消失。
3. drop 处理规则:
   - 若路径以 .json 结尾:读取 → JSON.parse → coerceItems → 若记录数 >0 弹现有 ImportChoiceModal(合并/覆盖)流程,复用 handleImportApply;解析失败 toast「JSON 解析失败」。
   - 若为 .txt/.md 或其他文本文件:读取内容(UTF-8),进入新建编辑态:body 预填文件内容,title 预填文件名去扩展名,source 预填「拖入:文件名」,tags 为空。
   - 多文件:只处理第一个,toast「一次仅处理一个文件」。
   - 纯文本拖放(无文件路径)一般拿不到,若 Tauri 事件只给 paths 则忽略。
4. 大小限制:.json > 10MB、文本 > 1MB 拒绝并 toast;读取失败(编码错误等)toast「读取失败,请确认是 UTF-8 文本」。

【实现要点】
- 新建 src/components/DropOverlay.tsx(纯展示,受控 visible)。
- App.tsx 挂 useEffect 注册 onDragDropEvent,返回的 unlisten 要清理;drop 时先关 overlay 再分发。
- 读取复用 api.ts 的 readDataFile(底层就是 fs::read_to_string);不要引入 fs 插件。
- 若调用 onDragDropEvent 时 Tauri 报权限错误,在 src-tauri/capabilities/default.json 的 permissions 补 core:webview:default,再试。
- 预填新建复用现有 prefillBody/prefillSeq 机制(DetailPane 已支持),不要新造一套。

【边界与异常】
- 正在编辑/弹窗打开时拖入:仍按规则处理(替换当前编辑态即可,提示"已载入拖入内容")。
- 回收站视图打开时拖入 .json:照常走导入;拖文本:切回主列表(trashOpen=false)再新建。
- 拖入目录:忽略并 toast「不支持文件夹」。

【不要做的事】
- 不要实现拖出/拖动排序;不要改数据格式;不要动 quickpick。
